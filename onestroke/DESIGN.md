# ワンストローク・ファクトリー 企画

マウスの一筆書きでベルトコンベアを引き、供給口→工場→納品口をつなぐパズル。

## 1. この企画の核（ここだけは外さない）

**一筆書き＝「順番」を設計すること。**

一本の線しか引けないので、ベルトは1レーンしかない。素材はその1レーンを列になって流れる。
つまりプレイヤーが決めているのは「どことどこを繋ぐか」ではなく、
**「素材がどの順番で機械を通るか」**。

- `鉄板の供給口 → ボルトの供給口 → 組立機 → 納品口` … 通る
- `組立機 → 鉄板 → ボルト → 納品口` … 組立機に何も届かず失敗

これで「1本の線」と「複数素材を使う工場」が矛盾なく両立する。
グラフを作るゲームではなく、**1本のパイプラインに機械を刺していくゲーム**。

これを成立させる唯一のルールが次。

> **機械は、自分に不要なものは素通りさせる。**

組立機が鉄板を待っている間にボルトが来たら、ボルトはそのまま通過して下流へ行く。
だから詰まらない。ベルトは常に流れている。

## 2. 遊びの流れ

1. 盤面（グリッド）に供給口・工場・納品口・壁が置かれている。配置は固定。
2. プレイヤーはマウスをドラッグして、空きマスとノードの上にベルトを一筆書きで引く。
3. **引いた瞬間から動き出す。** 実行ボタンはない。素材が流れ、機械が動く。
4. 納品口が必要個数を満たしたらクリア。
5. ダメなら引き直す。引き直しも一瞬。

「描く → 眺める」の待ち時間を作らない。常時稼働・即書き換えにする。
うまくいかないときは、**間違った物が線の終端からボロボロ落ちるのが見える**ので原因が分かる。

## 3. ルール

### ベルト
- グリッドの上下左右に伸ばす（斜めなし）。
- **同じマスを2回通れない**＝交差禁止。これが一筆書きの制約そのもの。
- 壁のマスには入れない。
- 引き始めが上流、引き終わりが下流。素材は始点→終点の向きに流れる。矢印で常時表示。
- 終端に着いた素材は落下＝廃棄。
- ステージごとに**使えるベルトの数に上限**がある。これが実質的な難度調整。

### ノード（すべて1マス。ベルトはその上を通過する）

| ノード | 挙動 |
|---|---|
| 供給口 | ベルトが上を通っていれば、そのマスが空いたとき素材を1つ載せる。無限。 |
| 工場（合成機） | レシピの未充足素材が来たら吸収。全部揃ったら数tick後に生成物を下流へ出す。不要な物は素通り。 |
| 加工機 | 単一素材の変換（鉄板→曲げ鉄板）。工場の簡易版。 |
| 複製機 | 通った素材を2個にする。「2個必要なレシピ」用。 |
| 納品口 | 指定された物だけ吸収してカウント。それ以外は素通り。 |
| 壁 | 通れない。ルートを縛る。 |

**ノードの横を通り過ぎてもいい。使わない供給口があってもいい。**
むしろ「通らない設計」が後半の鍵になる（下記）。

### クリアと評価（★3段階）
- ★1 … 納品達成
- ★2 … ベルト本数が目標以内
- ★3 … 廃棄ゼロ（1個も落とさない）

★3が効いてくる理由：不要な供給口を通ると、その素材はずっと垂れ流しになって落ち続ける。
**「通らないようにルートを引く」**という、交差禁止と噛み合った別種の難しさが生まれる。

## 4. なぜ面白いか

- 長い1本を引き切って、線が生き物みたいに動き出す瞬間の気持ちよさ。一筆書きは元々そういう快感がある。
- 「繋がった／繋がってない」の2択ではなく、**順番という見えない軸**があるので、
  正しい形に見える線が動かない → 見直す → 分かる、が起きる。
- 失敗が全部目で見える。何が足りないかを文章で説明しなくていい。
- 引き直しが速い。試行錯誤が作業にならない。

## 5. 操作

- ドラッグで描く。**引いてきた道を戻れば消える**（Flow Free方式）。
- 線の終端からドラッグ → 続きを描く／消す。
- それ以外の場所からドラッグ → 線を引き直し（既存は消える）。
- 右クリック or リセットボタンで全消去。
- マウスのみで完結。タッチも同じ操作で動く。

## 6. 見せ方

- 素材は**色＋形**で区別（丸／四角／三角／星＋色）。色だけに頼らない。
- ベルトは流れる縞模様で向きを表示。素材は等速で1マスずつ進む。
- 工場は素材を飲み込むとき・吐き出すときに小さく動く。
- 廃棄は終端からポトポト落として、画面下に積む（無言の減点表示）。

## 8. 実装メモ

- 置き場所: `website/onestroke/`（`index.html` + `game.js` + `style.css`）。`index.html` のカード一覧に追加。
- Canvas 2D で足りる規模。ビルド工程は作らない（`file://` で開ける）。
- ステージは `stages.js` にデータで持つ。盤面は文字列グリッドで書けるようにして、追加コストを下げる。
- シミュレーションは固定tick（例: 12tick/秒）で回し、描画は補間。
- 音は後から `sfx.js` 方式で足せるようにしておく（初版はなくてよい）。

## 9. 決め切っていない点

- 工場に入る素材の**個数比**（2:1など）を複製機だけで捌くか、供給口に「1回に2個」を持たせるか。→ まずは複製機のみで作り、足りなければ足す。
- 盤面サイズ。10×8 で始めて、後半 14×10 まで広げる想定。
- ★2のベルト本数目標は、実装後に自分で解いて決める。
