# 荒野の車載工房（ベータ 0.1）

メタルマックス風 × Slay the Spire × backpack battles。
`ActivityPlan/WebGame/WEBゲーム企画_メタルマックス風StS.md` の実装。

## 遊び方

`index.html` をブラウザで開くだけ。サーバも通信も要らない。

## 作り

絵は`website/tank/`と同じ方針で、実行時に canvas へ描く（画像ファイルは持たない）。
音は素材を同梱している（下記「音について」参照）。

| ファイル | 中身 |
|---|---|
| `data.js` | 車体・部品・敵・進行の数値。**調整はここだけ触れば足りる** |
| `art.js` | ドット絵。実行時に canvas へ描く。1マス16px |
| `sfx.js` | 効果音とBGM。`sfx/` `bgm/` の素材を再生する |
| `game.js` | 進行・配置・戦闘 |
| `style.css` / `index.html` | 画面 |
| `test.js` | 自動テスト。`?test=1` のときだけ動く。普段の起動には無関係 |

- ビルドなし・素のJS。`fetch` も ES modules も使っていないので `file://` でそのまま動く
  （音声再生も `Audio()` に直接ファイルを渡す方式で、`fetch`/`decodeAudioData` は使っていない）
- 保存は `localStorage`（キー `garage-run-v1`）

**この作りで守るべき制約は「ビルド無し」と「`file://` で動く」の2つだけ。**
CDNや同梱のライブラリはどちらとも衝突しないので、必要なら使ってよい
（`website/tank/` は Phaser 3 を CDN で読んでいる）。

## 自動テスト

`index.html?debug=1&test=1` で開くと `test.js` が動き、画面いっぱいに
PASS/FAIL の一覧が出る（本番の起動には一切関係ない。普通に `index.html` を
開いたときは正規表現が false を返して即終了するだけ）。

テストは `?debug=1` で生える `window.__garage` 越しにしか操作しない。
本物のセーブを壊さないよう、保存先も `garage-run-v1-test` のように
別キーへ変わり、実行のたびに空にしてから始める。

何を見ているか：
- ランの開始・初期装備・`build()` の数値
- 補助部品のオーラが「率」で乗ること（B-3の回帰確認。機関銃5→7、榴弾砲42→59）
- 装備を足すと同じ条件・同じ秒数でより多く削れること
  （敵側は`?debug=1`のAPIで固定値のダミーに差し替えるので、
  戦闘そのものに乱数が無いことを利用して毎回同じ結果になる）
- 消耗品・イベント効果・実績解除・図鑑の件数・保存の読み書き

追加するとき：`test.js` の `run()` に `ok('名前', 条件, 詳細)` を足すだけ。
狙った配置を作りたいときは `giveAt(G, 部品id, x, y)` で座標を直接上書きできる
（`canPlace` を通さないので、置けるかの判定ではなく効果の計算だけを見たいときに使う）。

`game.js` を書き換えるたび（とくに`D-1`のような内部構造の変更をするときは必ず）、
これを緑のまま保つこと。

## 熱（配置の芯）

**グリッドを「箱」から「盤」にするための仕組み。**
これが無かったころは、位置に依存する計算が補助部品の隣接ボーナスだけで、
しかも引力しかなかった（強い武器のまわりに補助を固めるのが常に最適）。
熱は**斥力**を作る。

ルールは4つ。

1. 武器は自分が乗っているマス全部に、毎秒 `heat / reload` の熱を出す
2. マスの排熱＝ `cellBase` ＋ 車体の `cool` ＋ 外気に触れている辺 × `openSide`
   ＋ 隣接する冷却器の `cool`
3. **隣のマス（別の武器）の発熱が `spill` の割合で回り込む** ← 武器どうしの反発はここ
4. 捨てきれない量（net）だけ、そのマスに乗っている武器のリロードが伸びる
   （武器の熱は、乗っているマスのうち一番苦しいマスで決まる）

そこから出てくること。

- 強い武器ほど熱いので、**主砲を固めると共倒れする**
- 外周は外気で冷え、内側はこもる。**塞がったマスは通気口**として働くので、
  開けると置ける代わりに排熱が減る（企画書の「穴追加」と噛み合う）
- 武器でない部品（エンジン等）は熱を出さないので、**武器の間の壁**になる
- 隣のマスを、照準装置（威力）と冷却器（熱）が奪い合う
- 車体ごとの `cool` が性格を作る。幌付きジープは風が通り（+0.8）、
  密閉された重戦車はこもる（-0.4）

**発熱に車体速度は掛けない。** 速い車体ほど熱くすると、速さが持ち味のジープだけが
二重に損をするうえ、なぜ熱いのかが画面から読み取れなくなるため。

プレイヤーへの見せ方：整備画面でマスを色分け（青＝余裕／橙＝加熱／赤＝過熱）、
過熱した部品には枠と「熱」の印、どの武器が何％遅いかを名指しで警告、
戦闘中も武器バーに「熱で◯% 遅い」と出す。

調整は `data.js` の `heat` にまとめてある。**`slowPer` を 0 にすればペナルティだけ消える**
（配置の採点や色分けはそのまま）。全部の `heat` を 0 にすれば熱そのものが消える。

## 改造（走行の性格を決める）

賞金首（中ボス）に勝つと、3択から1つ選ぶ**車そのものへの恒久変更**。
部品ではないのでマスを使わない。1周で最大2つ（賞金首は5階と9階）。

**すべての改造に代償を付ける。これがルール。** 利点だけの改造を足すと
ただの強化になって決断が消える。`data.js` の `mods` に追加するときも必ず代償を書く。

**効果と代償には「実際に効く資源」しか使わない。** 最初は積載と重量を通貨にしていたが、
この作りでは**マスのほうが先に埋まるので積載はまず超過しない**。
積載+10 も重さ−1 も、ほとんどの車で何も起きなかった。
使ってよいのは 装甲 / 被弾軽減 / 速度 / 排熱 / 弾 / マス / 戦闘後の回復。

`effect` に書ける鍵：

| 鍵 | 中身 |
|---|---|
| `hp` / `def` / `spd` | 最大装甲・被弾軽減・全体速度（加算。0.12 で+12%） |
| `cellCool` | 全マスの排熱の増減（熱の仕組みに効く） |
| `ammoFlat` / `ammoPct` | 弾数のある武器の弾（弾無限の副砲には効かない） |
| `healPct` | 戦闘に勝つたび最大装甲の n 割を回復 |
| `openAll` | 塞がったマスを全部開ける |

### カードに「いまの車がどうなるか」を出す

改造の数値は抽象的なので、**自分の車に当てた結果**を各カードに出している
（`modPreview()`）。実際に `S.mods` へ入れて `build()` し直しているので、
**予告と実際がずれない**（テストで全改造ぶん突き合わせている）。

色の意味を分けてあるのが要点。

- **緑＝得** / **赤＝損** / **灰＝数値は動くが、いまの車には効いていない**
- 得が一つも無いときは「いまの車には効き目がない」と明記する

数値が動くことと得をすることは別物で、混ぜると罠になる。
逆に、`healPct` のように**走行をまたいで効くもの**は `build()` を1回比べても出てこないので、
その改造だけ個別に行を足している。

## 敵の挙動（相性を作る）

**以前は7体中6体が「N秒ごとにXダメージ」だけで、何もしてこなかった**
（特殊挙動はボスの一斉射撃のみ）。そのため実測すると、
**どの敵でも構成の優劣が入れ替わらなかった**——装甲4の廃車ゴーレムでさえ、
重砲型29.5秒に対して手数型13.5秒。つまり敵の選択は
「弱い方を選ぶ」という難易度つまみで、相性の判断ではなかった。

いまは `behavior` で戦い方を要求する。**乱数は入れない。**

|敵|挙動|要求されるもの|
|---|---|---|
|野良ドローン|`speedUp` 時間とともに攻撃間隔が縮む|速攻|
|砂賊のバギー|`dodgeEvery` 4発に1発を避ける|手数。重い一撃ほど損|
|廃車ゴーレム|`armorPerHit` 撃たれるたび装甲+1|**重い一撃**。手数は自分で硬くする|
|自走砲スナイプ|（挙動なし）一撃が重い。次の攻撃ゲージを見て倒す|速攻|
|鉄クワガタ|`armorPerSec` 時間とともに装甲が増える|瞬発力|
|砂ヒル|`regen` 毎秒回復する|瞬発力|
|ゴルゴダ|`salvo` 15秒ごとに一斉射撃|—|

**肝は廃車ゴーレムと野良ドローンが正反対を要求すること。**
これで初めて構成の優劣が敵によって入れ替わり、
マップで道を選ぶ意味が生まれる（テーマ③と噛み合う）。

実測（同じ構成で比較）：

|敵|重砲型|手数型|
|---|---|---|
|廃車ゴーレム|**15.5秒**|29.5秒|
|野良ドローン|5.5秒|**4.5秒**|

**何をしてくる敵かは必ず画面に出す。** 分からないまま負けるのがいちばん悪い。
マップのノード説明、戦闘中の状態行（装甲が増えていく数字・加速中の表示）、
図鑑のカード、の3か所に `bnote` をそのまま出している。

挙動は `data.js` の `behavior` を消せば個別に無効化できる。

### 重い武器は「一発の重さ」で報われること

テーマ④で弾を絞ったとき、**重い武器を下げすぎて全部の敵に手数型が勝つ状態になった**。
155mm榴弾砲は3発で黙るので、装甲4の相手にさえ手数型の倍以上かかっていた。
威力を上げて（42→65、ミサイル48→75、レールキャノン88→140）ようやく
「数発で黙るが一撃が重い」という役が成立する。
**弾を絞るなら、そのぶん一発を重くすること。**

## 弾（戦闘に前半と後半を作る）

**弾はずっと「存在しない資源」だった。** いちばん長いボス戦でも
76mm速射砲は12/22発、105mmは8/16発しか使わず、半分以上余っていた。
そのため弾に乗っている仕組みが全部死んでいた——`stats.ammo`、
**弾薬箱**（貴重な隣接マスを1つ使うのに選ぶ理由が無い＝罠）、
**追加弾倉**、改造の**予備弾倉・弾薬庫**。

原因は、**全部の武器が「約20秒ぶんの弾」で揃っていた**こと
（10発×2.0秒＝20秒、7発×3.2秒＝22秒…）。戦闘は6〜23秒なので、
いちばん長い戦いだけがかろうじて届く。

いまは**重い武器ほど短く持つ**ようにしてある。

|武器|弾|撃ち続けられる時間|
|---|---|---|
|76mm速射砲|10|約20秒（支え役）|
|105mmライフル砲|5|約16秒|
|155mm榴弾砲|3|約14秒|
|ミサイルポッド|2|約12秒|
|レールキャノン|1|**一撃**。弾薬箱が前提|

これで長い戦いに**前半（主砲が火を噴く）と後半（副砲だけで削りきる）**ができる。
短い雑魚戦は3発しか撃たないのでほぼ変わらない。**効くのは賞金首とボスだけ**で、
戦いの種類ごとに手触りが分かれる。

- **12.7mm重機関銃に貫通1を持たせた。** 後半が弾無限の副砲だけになるので、
  そこが装甲に完全に弾かれると、ただ長引くだけの時間になる
- **車体に `ammo` を持たせた**（幌付きジープ +2）。手数の多い車ほど弾を食うので、
  速さが弾切れの早さに直結しないようにする
- 整備画面に**「弾が尽きるまで 約◯秒」**を出す。熱を色で見せるのと同じで、
  戦う前に分かっていないと構成が組めない

### 自動配置は「強くなる置き方」を選ぶ

`autoPlace()` は熱だけを見ていたため、**照準装置も弾薬箱も武器に接しない場所へ置かれ、
補助部品の効果をまるごと捨てていた**（威力+40%も弾+4も無効のまま）。
いまは `placementScore()`＝**毎秒火力（威力・リロード・熱を全部含む）を主、弾を従**
として最大化する。戦利品を受け取っただけでも補助が仕事をする。

## マップ（登り方を選ぶ）

**一本道は選択ではない。** 以前は次に進める先が1つだけの場面が47%あり、
2つ以上あっても38%は全部同じ種類だった（＝意味のある分岐は約3分の1）。
さらに線が地色とほぼ同色で、走り出す前は1本も見えていなかった。

いまの作り：

- **最上階（ボス）以外は必ず2つ以上へ分岐する**（`genMap`）
- 線は3段階で描く。**いま選べる道（橙）／この先まだ通れる道（灰青）／もう通れない道（暗い点線）**。
  辿り着けなくなったノードは沈める（`reachable()`）
- **戦う相手はマップ生成時に決めて、ノードに描く。** 一度戦った相手は名前も出る。
  入ってから抽選すると「見えていたもの」と違う敵が出て、道を選んだ意味が消える

### 種別の比率は動かさないこと

一度「分岐の行き先が全部同じ種類なら片方を別の種類に変える」ようにしたが、
**どの分岐にも戦闘以外の逃げ道ができて、戦闘を避けて登れてしまった**
（欲張りに避ける進み方で1走行の戦闘が **4.2回→1.0回**）。

敵をマップに出した以上、**「戦闘か戦闘か」はもう同じ選択ではない**
（固い相手と手数の多い相手のどちらを受けるか）。なので種別は入れ替えず、
**同じ階には違う敵を置く**だけにしてある。比率をいじるときは
「欲張りに避けたとき1走行に何回戦うか」を必ず測ること。

`drawMapLines()` はピクセルで線を引くので、**レイアウトが決まる前に測ると
幅0の `viewBox` ができて線が1本も出ない**（長いあいだこの状態だった）。
幅が取れるまで再試行し、ウィンドウのリサイズでも引き直している。

## 数値をいじるとき

ほぼ `data.js` で完結する。

- 部品：`weight`（重さ）/ `price` / `stats.dmg` / `stats.ammo` / `stats.reload` / `stats.pierce` / `stats.heat`
- 補助部品の隣接効果：`aura`（威力・弾）と `cool`（排熱）
- 熱の全体調整：`heat`（上の「熱」参照）
- 改造：`mods`（上の「改造」参照。**代償を必ず書く**）
- 車体：`cap` / `hp` / `def` / `spd` / `cool`（その車体の全マスの排熱）
- 敵：`hp` / `armor`（1発ごとに引く固定値）/ `atk` / `interval`
- 進行：`run.floors` / `run.scaleHp` / `run.scaleAtk`（雑魚の階層補正）/
  `run.eliteScaleHp` / `run.eliteScaleAtk`（中ボスの階層補正）

強化1段あたりの伸び（+22%など）と、休憩の回復量だけは `game.js` にある
（`eff()` と `renderRest()`）。

## 企画書との対応

- **消耗品**（徹甲弾・追加弾倉・タイルパック・応急パッチ）… 実装済み。持ち物として最大5個まで持ち、
  戦利品・行商で手に入る。効果は「次の戦闘だけ」（貫通・弾数）と「その場で永続」（マス開放・回復）の2系統
- **穴追加・穴をふさぐ** … 実装済み。車体には最初から塞がったマスがある（企画書の「穴をふさぐ」の逆）。
  ショップの「車体の増設」か、消耗品の「タイルパック」で開ける。値段は買うたびに上がる

## 更新するとき

`index.html` の `?v=X.Y` を書き換えないと、ブラウザが古いJSを読み続ける
（1ファイルだけ書き換え忘れると、新旧が食い違って壊れる）。手で直さず、
必ずこれを使う。

```bash
./bump-version.sh 1.3 1.4
```

## 動作確認用

`index.html?debug=1` を開くと `window.__garage` が生える。

```js
__garage.state()                       // セーブ状態
__garage.build()                       // 組み上がった性能
__garage.give('m_105')                 // 部品を足す
__garage.gold(999)
__garage.warpTo('boss')                // その種類のノードへ飛ぶ
__garage.meta()                        // 図鑑・実績・記録
__garage.resetMeta()                   // 記録だけ消す
__garage.step(60)                      // 戦闘を60秒ぶん進める（画面を待たない）
__garage.simulate('boss', 11, 10)      // 10回まわして勝率を見る
```
